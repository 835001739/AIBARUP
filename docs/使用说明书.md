# AIBAR 使用说明书

> 面向本机创作者的操作手册。配套：`docs/需求文档.md`、`docs/设计文档.md`、`docs/API_CONTRACT.md`。
> 适用环境：macOS / Linux，已安装 ComfyUI v0.30.0（conda `comfyui` 环境）与 AIBAR 隔离 venv（Python 3.13）。

---

## 1. 环境准备

1. **ComfyUI**：本机已部署 ComfyUI（默认 `127.0.0.1:8188`）。解释器用装了 torch 的那个 Python（本机为 conda `comfyui` 环境），AIBAR 不会用自身 `.venv` 启动它。
2. **AIBAR 依赖**：首次需创建隔离环境并装依赖（见 `requirements.txt`）。`.env` 提供端口、ComfyUI 目录、同步间隔等（参考 `.env.example`）。
3. **目录**：`COMFYUI_DIR` 指向 ComfyUI 根目录（用于同步深链扩展与出图）。未配置时部分联动能力降级。

---

## 2. 一键启动

在项目根目录执行：

```bash
./scripts/up.sh            # 等价于 start：先起 ComfyUI，再起 AIBAR
```

启动后会拉起两个服务并自动把 `comfyui_bridge/AIBAR-Bridge` 同步进 ComfyUI 的 `custom_nodes/`：

| 服务 | 地址 | 说明 |
|---|---|---|
| AIBAR | http://127.0.0.1:8099 | 主界面 |
| ComfyUI | http://127.0.0.1:8188 | 出图引擎 |

启动完成后浏览器打开 http://127.0.0.1:8099 即可。

**常用子命令**：

| 命令 | 作用 |
|---|---|
| `./scripts/up.sh start` | 启动（已运行的会跳过，不重复拉起） |
| `./scripts/up.sh stop` | 停止两个服务 |
| `./scripts/up.sh restart` | 重启；改了 Python 代码后用 `restart --force` |
| `./scripts/up.sh status` | 查看运行状态与地址、桥梁扩展是否安装 |
| `./scripts/up.sh open` | 在浏览器打开 AIBAR |
| `./scripts/up.sh bridge` | 仅同步 ComfyUI 桥梁扩展 |
| `./scripts/up.sh logs` | 跟踪两个服务日志（Ctrl-C 退出） |

> 提示：AIBAR 无 reloader。改 Python 后务必 `restart --force`；改前端 JS/HTML 只需刷新页面。
> `stop`/`restart` 默认不杀「非本脚本启动」的端口占用者；需强制清理时加 `--force`（小心误伤）。

**提示词工作台**内部有四个子视图（顶部切换）：

- **图片反推**：从图片恢复提示词（M9）。

## 4. 各功能使用

### 4.1 提示词扩写（M6）

1. 进入「提示词工作台 → 扩写」。
2. 输入一句提示词，选择 **模型档案**（如 `sd15_sdxl` / `flux_flux2` / `generic`）与 **强度**（保守 / 均衡 / 创意）。
3. 可选套用场景模板；Provider 默认可用 `rules`（确定性，无需联网）。
4. 点击扩写：返回原始提示词、扩写正 / 负向、分维度段落、新增说明与警告；耗时通常数毫秒。
5. 结果可复制、保存到历史、收藏、删除、应用模板。

> 规则：空输入 / 仅标点 / 超 2000 字符 / 未知强度会被拒绝（400）。sd15_sdxl 输出正负向；flux 系列输出自然语言无负向。

### 4.2 词库浏览与检索（M7）

1. 进入「词库」。
2. 顶部切换 **媒体类型**：图片 / 视频 / 歌曲。
3. **渐进分面筛选**：维度、子分类、标签、模型档案、来源均可点选，且只显示当前条件下仍有数据的选项（无空层级）。
4. **搜索**：关键词匹配标题 / 提示词；**排序**：推荐 / 最近 / 最近使用 / 最多使用；**收藏** 可筛选仅看收藏。
5. **分页**：列表带翻页，超过一页可翻（不再静默截断）。
6. **回填**：点击词条 → 光标处插入提示词（自动去重，可撤销），不自动触发扩写；使用次数随之 +1。
7. **写操作**：工具栏「新建词条」、词条卡片「编辑 / 删除」。内置词条删除表现为本地隐藏并写入忽略指纹（不物理丢失）。

### 4.3 候选审核（M7 自动学习）

- 「候选审核」按钮带待审数量徽标。
- 低置信度生成片段进入候选，可 **通过**（指定维度 / 子分类 / 标题入库）或 **拒绝**（写入忽略指纹，不再重复出现）。

### 4.4 图片反推（M9）

1. 进入「图片反推」。
2. **上传图片**（png/jpg/jpeg/webp，≤20MB）：自动校验真实图片内容，动画 / 损坏文件会被拒绝（415）。
3. 选择 **来源模式**：自动 / 元数据 / 视觉；**模型档案** 与 **精度**（快 / 标准 / 细）；**Provider**（自动 / 指定）。
4. 建议用 **异步**（`async:true`）并提交，界面按后端真实阶段（排队 → 读取 → 元数据 / 视觉 → 结构化 → 完成）轮询进度，不再有假进度条。
5. 结果分段展示（主体与外观、构图、灯光等维度），每段可编辑、可勾选「入词库」。
6. 点击 **保存**：高置信度入库、低置信度进候选、已存在 / 拒绝 / 失败均正确处理；返回 `{inserted, merged, candidates, discarded}`。
7. 来源清晰标注：原始提示词恢复（metadata）或 视觉模型（vision）；来源图只存受控哈希引用，不泄露原始路径。

### 4.5 工作流与出图（M2）

1. 进入「工作流」查看已同步卡片（名称、节点数、节点类型、正 / 负提示词预览）。
2. 点击卡片 **详情** 看节点清单与提示词全文；可 **下载** 原始 JSON。
3. **用 ComfyUI 出图**：卡片按钮把 UI 工作流转 API prompt 图，提交 ComfyUI 生成，抽屉内轮询产出并同源渲染（实测一次出 8 张）。
4. **在 ComfyUI 编辑器中打开**：深链到 ComfyUI 并载入该工作流 + 提示词（需桥梁扩展已同步）。

### 4.6 画廊与溯源（M3）

- 进入「画廊」分页浏览成图；点击进入灯箱看完整元数据（尺寸、字节、提示词、工作流链接）。
- 「溯源」可跳转到对应工作流（`GET /gallery/<id>/workflow`）。

### 4.7 案例库 / 模型

- 「案例库」：派生自工作流的可复用案例，按风格筛选。
- 「模型」：已扫描的本地模型清单（名称、类型、路径、大小）。

### 4.8 同步与日志（M4）

- 「同步日志」查看同步记录（时间、类型、消息、状态）。
- 通过接口或界面切换 **自动同步**；新图通常 10–20s 内出现在画廊。

### 4.9 漫画工作室（M12）

漫画工作室维护「生产漫画」的大工作流：自上而下是 **项目 → 章节 → 分镜页** 三层，每页带一张预制提示词 + 出图工作流 + 随机种子；通过 ComfyUI 出图队列把预制提示词变成成图，成图后仍可对单张分镜**重新生成**。

**① 漫画概览（首页）**

1. 进入「漫画工作室」，首屏是项目卡片网格，每张卡显示：标题、状态徽标（草稿 / 制作中 / 完成）、以及聚合的 **章节数 · 分镜页数 · 已完成页数**。
2. 顶部可按项目状态筛选；点击卡片进入项目详情。

**② 项目详情**

1. 面包屑可返回概览；元信息条显示项目状态与备注。
2. 工具栏：**新建章节** / **出图全本** / **编辑** / **删除**。
3. 章节列表：点击进入章节详情；可逐章管理。
4. 队列表格：展示该项目下的出图任务（页、状态、错误码），排队中可 **取消**。

**③ 章节详情**

1. 面包屑返回项目；元信息显示章节标题、序号、状态。
2. 工具栏：**新建分镜** / **出图整章** / **编辑** / **删除**。
3. 分镜列表（每章节的所有图片）：每张卡含——
   - 预制提示词 `prompt_text` 与负向 `negative_text`；
   - 关联出图工作流 `workflow_filename`（来自「工作流」同步）；
   - 随机种子 `seed`；
   - 当前状态（待生成 / 排队中 / 生成中 / 已完成 / 失败）；
   - 若已出图，显示成图预览；
   - 操作：**生成**（首次出图）/ **重生成**（大工作流完成后对任意单图重出）/ **反推提示词**（仅已完成页；把该页成图送进 M9 反推，复用图库深链）/ **重扩写**（任意页；用剧情原文重新扩写并重排提示词，见 ⑩）/ **编辑**（改提示词 / 工作流 / 种子）/ **删除**。

**④ ComfyUI 出图队列**

- 点 **生成** / **重生成** / **出图整章** / **出图全本** 后，对应分镜页进入「排队中」，后台 worker 把预制提示词注入工作流并提交 ComfyUI 生成，轮询产出后下载首张成图写回页（状态转「已完成」并出现预览）。
- 项目详情的队列表格中，排队中的任务可 **取消**（仅把该页重置回「待生成」，不影响已经「已完成」的页）。
- 活跃任务会自动每 4 秒刷新队列状态，无需手动刷新。

**⑤ 从 Skill 导入工作流（把任意 skill 的流程变成漫画大工作流）**

- 在「漫画工作室」概览页顶部工具栏点 **导入 Skill 工作流**，弹窗中：
  - 粘贴 `SKILL.md` 全文（优先），或填写本地 `SKILL.md` 路径，二者选一；
  - 可选填「漫画名称」（留空则用 skill 的 `name`）与「出图工作流文件」（留空则自动写入 FLUX.2 最小化工作流）。
- 确认后自动创建：漫画项目（= skill 名）→ 章节（= `## 段落`；说明性段落如 When to use / 前置条件 / Pitfalls / Verification / Files 自动跳过）→ 分镜页（= 段落内编号步骤，`prompt_text` = 步骤原文，出图前可在页内编辑为真正的图像提示词）。
- 导入成功自动跳转到该漫画项目；之后即可像普通漫画一样逐页 **生成** 出图。
- 这是**可复用能力**：任何 skill 都能照此转成本项目的漫画大工作流，无需改代码——实现「skill 的流程 → 本项目能力」的沉淀。

> 注意：出图依赖本机 ComfyUI 可达且 `workflow_filename` 对应工作流含 SaveImage 节点（否则取不到首张成图，页会标记「失败」并记 `error_code`）。ComfyUI 已停止时，入队任务保持「排队中」，待 ComfyUI 恢复后 worker 即可继续处理。

**⑥ 分镜工作流（世界观 + 剧情摘要 → 自动分集出图）**

- 项目详情页顶部有「分镜工作流」面板，含两个可编辑文本框：**世界观** 与 **剧情摘要**、**出图数量（每章页数）** 数字输入框（范围 1~12，默认 1，存于 `comic_projects.pages_per_chapter`），以及 **出图风格** 下拉框（存于 `comic_projects.style_preset`，默认「不限制」）。
  - 点 **保存设定** 把世界观 / 剧情摘要 / 出图数量 / 出图风格一并写回项目。
  - 点 **自动生成分镜出图**（或项目工具栏 **自动分镜**）即按当前内容一键生成：自动把剧情拆成 N 集，按「出图数量」把每集剧情转换为对应页数的分镜页，按「出图风格」为每一页规范提示词，建「集 = 章节、每集 N 页 = 分镜页」并自动入队出图。
  - 工具栏 **自动分镜** 会先弹出「生成模式」选择：
    - **追加**（默认）：保留已有章节，新分集排在后面；
    - **重建**：先清空该项目所有已有章节（连带分镜页与队列任务）再生成 —— **改完剧情重新生成时用这个**，否则会不断叠加出重复的分集。
- **分集拆分**：剧情摘要按「第N集 / 第N话 / EPn / 数字.数字 / （数字）」标记或空行分段；单段落内联编号（如「1. a 2. b」）也会拆分；无标记则整体作为一集（上限 24 集）。
- **出图数量（每章页数）**：决定每集拆出几张分镜页。每集剧情会被转换为该数量的画面描述 —— 先按句切分，句数足够则均匀取句；句数不足时**循环复用已有句子**（而不是全部堆在末句上）并为每一页叠加不同的镜头景别（远景 / 中景 / 近景 / 特写 / 过肩 / 俯仰 / 动态 / 空镜 等），保证每页提示词独立、页与页之间有区分度。例如「出图数量 = 3」+ 两集剧情 → 2 章 × 3 页 = 6 张分镜入队。每页的景别会显示在分镜卡片上（如「景别：中景」）。
- **出图风格（风格统一）**：可选「不限制 / 日式黑白漫画 / 新海诚动画电影风 / 美式漫画 / 国风水墨 / 水彩绘本 / 赛博朋克 / 像素游戏风 / 写实厚涂插画」。选定后，**每一集的每一页**提示词都会追加**完全相同**的一段风格描述词，并合并同一套排除项（如黑白漫画会排除彩色、照片、3D 渲染），从而保证整部漫画每一集的画面风格统一。风格可随时在下拉框更换，下次生成的分镜页即用新风格（已生成的分镜页可单独编辑提示词）。风格词使用英文标签（图像模型对英文风格词响应最稳定），界面名称为中文。
- **扩写**：每个分镜页画面描述用提示词扩写引擎补画面维度（光线 / 构图 / 材质 / 色彩等）；`AI_PROVIDER_*` 启用时尝试用 LLM 拆分与扩写，失败自动回退规则引擎。
- **零配置出图**：项目未设默认工作流时，自动写入 FLUX.2 最小化工作流并设为默认；分镜页继承后即可经 ComfyUI 出图。
- **查看成图**：每集对应一个章节，生成后在「章节管理」点开该章节即可看到该集的各张分镜页与产出图片（与 ③ 章节详情一致）。

**⑦ 角色卡（人物一致性）**

- 项目详情页「分镜工作流」面板下方是 **角色一致性（人物锚点）** 面板，列出本项目所有角色卡（工具栏另有 **重刷提示词**，见 ⑦′）。
  - 点 **从剧本抽取**：自动从世界观 / 剧情摘要里识别人物并建卡（只新增缺失角色，**不会覆盖**你手填的描述）。
  - 点 **新建角色** 手动建卡：**名字** 必填，**外貌**（发色/发型/五官/体型）、**服装**、**配色** 建议尽量填全 —— 这几项会拼成固定锚点。**排除项** 可写「不要改变发色」这类约束。**别名** 用于匹配剧本里的其他称呼（如「小岚、岚儿」）。
  - 每张卡底部会显示 **锚点** 预览，即实际注入提示词的文本。
- **主角（贯穿全本）**：角色卡上的 **主角** 徽标表示这张卡会注入到**每一页**，哪怕某一页的文案里没提他的名字（比如「他走进森林」这种写法），人物特征也不会丢。第一个被创建 / 抽取出来的角色默认是主角；每张卡都有 **设为主角 / 取消主角** 按钮可随时切换。
- **一致性是怎么保证的**：生成分镜时，凡是这一页提到了某个角色（或是主角），就把该角色**逐字相同**的锚点插到提示词最前面（图像模型对靠前的描述权重更高），同时把该角色的「排除项」并入负面提示词，并用「角色组合」参与页级种子派生 —— 于是同一角色跨页、跨集长得一致，重跑也能复现。
- 角色卡随时可编辑 / 删除，上限 12 个。

**⑦′ 重刷提示词（改完角色卡一键同步全本）**

- 角色面板工具栏点 **重刷提示词**，可按**当前**角色卡 / 世界观 / 出图风格，重算这个项目所有分镜页的提示词与种子。
- 弹窗里可以选：
  - **出图风格**：默认「沿用当前风格」，也可顺手换成别的风格；
  - **重算后自动出图**：`只重跑失败的页`（推荐，默认）/ `全部页重新出图` / `只改提示词，先不出图`。
- **为什么需要它**：角色卡只是「模板」，改了外貌之后已生成的几十页提示词还停在旧版本。重刷会重做「注入锚点 → 合并排除项 → 套用风格 → 派生种子」这一步，**不重新拆分剧情、不重新扩写**，因此不会打乱已有分镜，改完立刻全本生效。
- 它是**幂等**的：同样条件下重复点，结果完全一致（提示「0 页内容有变化」），可以放心当同步按钮用。

**⑧ 出图进度**

- 角色面板下方是 **出图进度** 卡，展示：总进度条与「已完成 / 总数（百分比）」、ComfyUI 在线/离线状态、各状态页数（待出图 / 排队 / 生成中 / 已完成 / 失败）、队列任务数、角色卡数量，以及**分集进度**（每一集一条细进度条）。
- 有任务在跑时进度每 3 秒自动局部刷新（只重画进度 / 章节 / 队列，**不会打断你正在填写的输入框**）。
- 出错时显示 **中文失败原因**（如「提交到 ComfyUI 失败」）与失败原因分布（如 `submit_failed × 6`）。
- 还有活儿在跑时会显示 **正在出图的页** 与 **预计剩余时间**（按最近几张图的实测均速估算）。
- **自动重试**：ComfyUI 离线、提交失败、超时这类可恢复故障会自动退避重试，最多 3 次；ComfyUI 启动后会接着跑，无需手动重排。

**⑨ 出图体检（ComfyUI 衔接）**

- 项目工具栏点 **出图体检**，会检查并给出中文建议：ComfyUI 是否在线（含响应耗时）、工作流文件是否存在及其节点数、节点是否都已安装、队列是否拥堵。
- 每张分镜页都有 **在 ComfyUI 打开** 按钮：会用该页的提示词 + 排除项 + 工作流，在 ComfyUI 里直接载入，方便手工微调后立刻出图。

**⑩ 产出图回流图库 / 单页重扩写 / 按条件重出图（本轮打磨新增）**

- **产出图回流图库（F1）**：漫画产出图原本只写在 `data/comic_outputs`，不进图库，导致「反推提示词」「图库溯源」对漫画页用不了。现在每张分镜页出图成功后会自动把成图注册进图库 `images` 表（`static/gallery` 副本 + 内容 sha256 去重），并写回页 `image_id`。项目工具栏的 **同步图库** 可对任意项目（或全部项目）补跑回流——**已出图但图库里没有的页**会被补齐，**产出文件已被 ComfyUI 移走**的页会被清掉悬空引用，卡片老实显示「未出图」而不是裂图。回流后已完成页才出现 **反推提示词** 按钮（见上）。
- **单页重扩写（F3）**：每张分镜页都有 **重扩写** 按钮——它用分镜工作流落库的「剧情原文」（`beat_text`）重新跑扩写引擎，并按**当前**角色锚点 / 出图风格重组成图提示词，写回页 `prompt_text`/`negative_text`。适合「剧情改了 / 角色外貌改了，只想让这一页重新长」的场景；重刷提示词是整本级，重扩写是单页级、且会重新扩写（不只是重排）。若某页没有剧情原文，会跳过扩写、只按当前锚点重排，并给提示。勾选「重新出图」可顺带把该页重新入队。
- **按条件批量重出图（F4）**：项目工具栏的 **按条件重出** 弹窗，让你选「出图范围」——全部页 / 只重跑失败的 / 只跑还没出图的——再一键批量入队，不必整本重出也不必逐页点。弹窗实时显示各范围页数（如「全部页 7 张 / 失败的 0 张 / 未出图的 1 张」），按数字确认后再提交。

### 4.10 组图（M14）

组图 = **同一人物做连贯动作**的有序帧序列，出完一张可连播成动画（像 GIF 一样）。和漫画分镜（每页是不同场景）的关键差别是：**分镜跟着剧情走，组图只让同一张脸在不同动作里反复出现**。

**① 强制预设提示词（核心机制）**

组图上一次性设定三段强制预设：

| 字段 | 角色 | 例 |
|---|---|---|
| `preset_prefix` | 场景 / 画风（所有帧共用） | 「古风庭院，黄昏，薄雾」 |
| `preset_suffix` | 镜头 / 画质（所有帧共用） | 「电影感侧光，浅景深，全身构图」 |
| `preset_negative` | 强制负面词（所有帧共用） | 「blurry, watermark」 |

帧只提供 `action_text`（这一帧做什么动作：「抬手指向远方」「握紧刀柄」「拔出长刀」）。最终提示词恒由预设拼装：**人物锚点 → 一致性指令 → 前缀 → 动作 → 后缀**。改了预设点「保存后按新预设重算全部帧提示词」即可同步全部帧——单帧改不动提示词，这是「强制」的含义，也是连播时人物不漂、画风不跳的根本保障。

**② 绑定演员（强烈建议）**

在「新建 / 编辑组图」里给 **绑定演员** 选一个演员——演员定妆信息会作为人物锚点注入每一帧，**这是连播时脸不漂的唯一保证**。不绑演员就要在「人物设定补充」里手填完整的角色描述（外貌 / 服装 / 配色），否则每一帧只有动作、没有人，画面会变成不同的人轮流做同一套动作。

**③ 连贯动作的种子策略**

种子默认 `seed_step=0`（**所有帧共用同一个种子**）——同种子 + 不同动作文本 = 模型保留人物与构图、只改动作描述 = 连播即「同一人做连续动作」的物理基础。每帧换种子会变「换脸动画」，必须调大 `seed_step`（代价是脸开始漂移）。

**④ 整组出图（串行）**

点 **出图** 入队——AIBAR 串行跑（ComfyUI 单卡排队，并发只会互相抢显存），每帧约 60 秒，整组几分钟。卡片实时显示「出图 done=X/3」进度。要中途停止点 **取消出图**（让当前帧跑完再停，不硬杀线程）。

只跑「没出过 / 失败」的帧：弹窗里取消勾选就会重出全部（适合「想统一换一张脸」的场景）。

**⑤ 动作帧管理（逐帧卡片）**

点 **动作帧** 打开管理弹窗——**默认逐帧卡片视图**：每张卡显示缩略图、动作文本、状态徽标（已出 / 出图中 / 失败 / 待出）与错误原因。卡片上直接做：

- **上移 / 下移**：调整连播顺序
- **重生成**：单独重出该帧（适合「就这一张表情不对」）
- **删除**：删帧并把后续帧序前移（连播不会跳号）
- **点击动作文本**：内联编辑该帧的动作描述，提示词自动按当前预设重算

需要一次性替换所有动作？点 **批量编辑** 折叠入口，多行文本框里「一行一个动作」覆盖保存。

**⑥ 连播（GIF 式）**

点组图封面（缩略图上有播放图标）即打开播放器：

- 出过图的帧全部预加载到内存，播放时只切 `src`，**不会闪白**
- 打开即播（默认循环），点 **暂停** 停下
- 进度条既是进度也是可拖动定位器
- 速度：0.5× / 1× / 2× / 4×（围绕本组 `frame_interval` 动态生成，跟用户设的间隔对齐）
- 快捷键：**空格** 播放/暂停、**← / →** 逐帧切换

**⑦ 常见排障**

| 现象 | 原因 / 处理 |
|---|---|
| 卡片一直显示「出图中」 | 上一轮进程被 kill 时跑着的帧卡死（`_claim_frame` 拒绝接管）。AIBAR 重启 15 分钟后会自动 reap，或手动调 `POST /api/comic/maintenance/frames-reap` 立即清理，被卡的帧会变成「失败」并在卡片上提示「请点重生成」。 |
| 调大 `seed_step` 后人物越来越不像 | 种子步长超过 ~50 时模型换脸风险显著；连播想要「动作幅度大但脸稳」，改 `preset_suffix` 里的「构图」提示词比改 seed 更稳。 |
| 连播速度档不对 | 速度档围绕本组 `frame_interval` 动态生成；如果一档明显太快/太慢，编辑组图改 `frame_interval`（连播毫秒）。 |
| 删了一帧但播放器仍显示空位 | 删帧后调「批量编辑」点保存一次，把 server 端的 `frames[]` 与播放清单 playlist 同步；或整组重出一次。 |

### 4.11 视频转帧（M15）

把一段视频拆成序列帧、合成 GIF，还能**按颜色抠掉背景**做透明帧、**拼成序列帧图**。序列帧用于逐帧二次编辑，GIF 用于贴进文档 / 聊天窗口，连播用于快速预览，透明帧和序列帧图适合拿去做 sprite / 贴图。

**① 导入视频**

两种入口，按视频在哪选：

| 入口 | 适用 | 说明 |
|---|---|---|
| **导入视频** | 视频在本地，要上传 | multipart 上传，落盘到 `data/video_sources/`，上限 500MB |
| **导入本地路径** | 视频已在磁盘上 | 只登记路径**不复制**，适合大视频 |

导入后会用 ffprobe 自动读出时长 / 分辨率 / 帧率，显示在卡片上。

**② 抽序列帧**

点卡片上的 **抽帧**，可调：

- **每秒帧数 (fps)** —— 默认 8。GIF 用 8 足够，做逐帧精修可调高。
- **最多帧数** —— 默认 300，硬上限 1000。防止长视频把磁盘撑爆。
- **输出宽度** —— 默认 480，高度按比例。
- **起始 / 结束秒** —— 只截片段时填。

抽帧是**幂等**的：每次先清空该视频已有的帧再重新生成，不会新旧参数的文件混在一起。

**③ 转 GIF**

必须先抽帧。**GIF 是从已抽出的帧合成的**，不是从原视频重抽——这样你预览看到的序列帧，就是 GIF 里播放的内容。

技术上用 ffmpeg 两遍 palette 法（先生成 256 色调色板，再套用），颜色比直接转准得多，渐变不会有明显色带。

**④ 序列帧连播**

抽完帧后点 **播放**，打开连播播放器：

- 全部帧预加载后逐帧切换，**不会闪白**
- 打开即播（默认循环），**空格** 播放/暂停，**← / →** 逐帧
- 进度条可拖动定位
- 速度 0.5× / 1×（原速）/ 2× / 4× —— 原速默认按视频 fps 走

这个播放器与组图连播是同一份代码（`static/js/player.js`），两边修 bug 一起生效。

**⑤ 下载与删除**

- **GIF** 按钮直接下载 GIF 文件
- **删除** 会清掉记录、帧目录和 GIF。**注意**：从本机路径导入的视频，原始文件不会被删（那可能是你唯一的原件）；上传的会一并清除。

**⑥ 去背景（抠图）**

点卡片上的 **去背景**（滤镜图标），弹窗里：

- **模式**：二选一。
  - **按颜色抠（整图）**：把接近某颜色的全部像素变透明（见下「双色抠图」）。
  - **连通抠图（只抠选点连通背景）**：你**在图上点的那个点**就是种子；只移除与它
    **连通**的背景，画面里另一块同色但被主体隔开的区域会**保留**。适合「只要左上角
    这块背景、别动其它同色区域」的场景。
- **从图片取色（推荐）**：弹窗内嵌第一帧预览图，鼠标移到图上会跟随十字准星，
  **点击 / 拖拽**即可读取该点像素的 `#RRGGBB`，自动同步到色块与右侧 hex 输入框
  （三者双向同步）。比凭肉眼估颜色准得多。
- **手填色值**：也可直接点色块用系统取色器，或在右侧输入框手填 `#RRGGBB`。
  颜色不填则复用上次。
- **容差**：0–1，背景不纯（JPG 压缩噪点）要给够，默认 0.3。太小会留一圈未抠净的硬边。
- **羽化**：0–1，默认 0.05，让抠边更柔、不锯齿。

**双色抠图**：勾选「双色抠图（按两种背景色一起抠透明）」后，出现第二把钥匙
行与取色目标切换（`取色到 色1` / `取色到 色2`）。在图上取色时会写入当前选中的
目标；`similarity2` / `blend2` 不填则复用第一把钥匙的容差 / 羽化。结果是
**接近任意一把钥匙色的像素都变透明**——适合同时抠掉绿幕 + 蓝幕两种背景。

**连通抠图**：在「模式」里选「连通抠图（只抠选点连通背景）」后，弹窗出现「种子点」
一行（默认 `左上角 (0, 0)`）。**在图片上点击任意位置**即把该点设为种子（坐标实时
显示），也可点「重置为左上角」回到默认。种子点所在的背景色即为抠除基准：

- 只移除**从种子点 4-连通可达、且颜色接近种子色**的像素；
- 同一画面里**被主体隔开的同色背景块**不会被波及（不连通 → 保留）；
- 背景若有渐变 / 偏色，远离种子色的部分会自动停住，**不会顺着渐变扩散**到主体；
- 连通模式用「种子点颜色」做基准，**忽略双色参数**，容差 / 羽化照常生效。

确认后会在 `nobg/` 子目录生成**带透明通道的 PNG**，原帧**完全不动**；卡片自动切到「透明」变体，封面用棋盘格背景表示透明区。可选 **清除去背景** 退回原图（只删 `nobg` 目录，可逆，双色的第二把钥匙也会一并复位）。

透明帧可在 **序列帧连播 / 拼图 / GIF** 里切换「原图 / 透明」变体查看与导出。

**⑦ 拼序列帧图**

点卡片上的 **拼图**（图片图标），弹窗里设：

- **列数**：1–50，默认 5（行数按帧数自动算）。
- **间距**：0–50px，默认 0。

确认后把当前变体的全部帧拼成一张网格图，可点 **大图** 按钮下载。透明变体拼出的图也是透明的（PNG, RGBA）。

**排障**

| 现象 | 处理 |
|---|---|
| 提示「未找到 ffmpeg」 | 装 `brew install ffmpeg`，或把它加进 PATH |
| 抽帧超时 / 太慢 | 调小「最多帧数」或缩短时间区间（默认超时 180s） |
| GIF 颜色发灰有色带 | 已用 palette 法；可试降低 fps 或减小输出宽度 |
| 去背景后边缘留绿/留硬边 | 调大「容差」；仍有锯齿就加一点「羽化」 |
| 去背景没反应 / 报「颜色格式不对」 | 颜色必须填 `#RRGGBB`（含 #），如 `#00FF00`；不能填颜色名（green 等） |
| 导入后时长/分辨率是 `—` | ffprobe 读不出该格式；换 mp4 / mov 再试 |

### 4.12 视频转绘（M16）

把一段视频**逐帧拆成骨架**，再用**参考图锁脸 + 骨架控姿**，逐帧重绘成统一风格，最后落进「组图管理」连播。一句话：**视频 → 动作拆解 → 重绘成同一批角色的统一风格图 → 可连播的组图**。

与 M15（只拆帧 / 转 GIF / 去背景）不同，M16 在抽帧之上多了两步：**提骨架（DWPreprocessor）** 与 **ComfyUI 逐帧重绘（姿势可控 + 锁脸）**，并把结果直接写回组图，生成后即可在「组图管理」里连播。

**① 新建视频转绘**

点左侧导航「视频转绘」→「新建视频转绘」，弹窗里填：

- **源视频**：从 M15 已导入并抽过帧的视频里挑一个（下拉）。没抽过帧的视频先去 M15 抽一版。
- **参考图**：三选一——本地上传 / 填本机绝对路径 / 填已在 ComfyUI `input` 里的文件名。参考图用于 IPAdapter FaceID 锁脸，建议用**正面清晰大头照**。
- **正向 / 负向提示词**：描述目标画风与角色（如 `1girl, blue coat, anime style, cinematic lighting`）。
- **生成参数**：姿态模型（dwpose / openpose）、姿态分辨率、步数、CFG、ControlNet 强度、IPAdapter 权重、FaceID 权重、宽高、种子（base_seed + seed_step 逐帧偏移，保证连播脸不漂）、抽帧参数（fps / 最多帧数 / 输出宽度 / 起止秒）。

确认后建一个任务，状态 `待准备`。

**② 五步流水线**

任务详情页的「流水线」区有 5 个按钮，按顺序点：

| 步骤 | 按钮 | 做什么 | 完成态 |
|---|---|---|---|
| ① | 抽帧准备 | 从视频抽帧 → 在组图管理建一份组图 + 逐帧登记 | `已抽帧` |
| ② | 动作拆解 | 每帧上传 ComfyUI → DWPreprocessor / OpenposePreprocessor 提骨架 | `已拆解` |
| ③ | 逐帧重绘 | 骨架 + 参考图喂进姿势可控工作流重绘，写回组图 | `已完成` |
| ④ | 去背景 | 对生成图做连通抠图（纯 PIL），出透明序列帧 | `has_nobg=1` |
| ⑤ | 拼组图 | 把生成图（或去背景图）拼成一张序列帧大图 | 产出 sheet |

前一步是后一步的前置，未完成的步骤按钮置灰。抽帧 / 拆解 / 重绘是长任务（驱动 ComfyUI，每帧数秒到数十秒），期间按钮进入忙态、不可重复点；去背景 / 拼图相对快。某帧失败不影响其它帧：重绘后状态为 `已完成`（全成功）或 `部分完成`（部分失败，详见逐帧预览的失败标记）。

**③ 逐帧预览对比**

详情页下方「逐帧预览」把每一帧的四种产物并排：

- **源帧**：抽帧原图（动作拆解前的样子）；
- **骨架**：② 提的姿态骨架；
- **生成**：③ 重绘结果；
- **去背景**：④ 透明版（没跑过去背景这格显示占位）。

这样你能一眼看出「姿态对不对、脸锁住没、风格统一没」。

**④ 连播与落组图**

- 点 **连播生成序列** 打开通用播放器，只播 `生成` 成功的帧（`AIBAR.player.open`，与组图 / 视频连播同一份代码）。
- 点 **查看组图** 跳到「组图管理」对应组图，直接连播 / 下载 / 二次编辑——因为 ③ 重绘时已经把图写回 `shot_frames`。

**⑤ 工作流按钮（进 ComfyUI 画布细调 / 重新指定帧）**

每一帧卡片右下角有一个 **工作流** 按钮，详情页操作区也有一个 **打开工作流** 按钮。点击后会**在浏览器新标签打开 ComfyUI（:8188）并自动载入这一帧的姿态重绘工作流**（参考图锁脸 + 骨架控姿的完整链路），你可以在画布里：

- 调参数：步数 / CFG / ControlNet 强度 / IPAdapter 权重 / 宽高 / 种子等；
- 换参考图：改 `LoadImage(参考图)` 指向 ComfyUI `input` 里另一张图，换锁脸对象；
- **重新指定帧**：把 `LoadImage(骨架)` 换成另一帧的骨架文件名（`aibar_vp_pose_<job>_<order>.png`），即可对别的帧重绘；
- 改提示词、加节点、连别的模型，然后**多次出图**做对比。

> 前置：该帧须先经过 **动作拆解**（有骨架图），否则按钮置灰、点开也会提示先 `pose`/`generate`。工作流由 AIBAR 后端即时生成（UI 格式），依赖 `AIBAR-Bridge` 扩展自动载入；若扩展未装，深链接只打开 ComfyUI 首页。

**排障**

| 现象 | 处理 |
|---|---|
| 新建时提示「源视频不存在」 | 先在 M15 导入并抽帧，下拉里才会出现 |
| 动作拆解报「ComfyUI 不可达」 | 先在首页确认 ComfyUI 在线（8188），M16 拆解 / 重绘都依赖它 |
| 重绘后脸没锁住 | 参考图换正面清晰大头照；调高 `IPAdapter 权重` / `FaceID 权重` |
| 重绘后姿态歪了 | 调高 `ControlNet 强度`；或换 `openpose` 姿态模型 |
| 逐帧风格跳 | 同种子 + 不同动作 = 连贯动作的关键；把 `seed_step` 调小（甚至 0） |
| 去背景留硬边 | 调大「容差」，加一点「羽化」（与 M15 去背景同套参数语义） |
| 删除报「正在执行中」 | 等当前流水线跑完再删 |

| 想换 9B / base 版 | 改 `diffusion="flux-2-klein-9b.safetensors"`（需要先下载）或 `flux-2-klein-base-4b.safetensors`（多样高、50 步）+ `steps=50, cfg=4.0` |

### 4.14 FLUX.2 姿势参考 + 人物一致（M17.3）

> 与 §4.13 的区别：§4.13 是**单参考图结构控制**（一张外观图 + 一张结构图）；
> 本节是**多人设参考 + 姿势参考**，目标是「跨帧换姿势但人物长得一样」——
> 视频转绘 / 漫画分镜这类「同一个角色连续出多张」的场景用这个。

#### 入口与文件

| 文件 | 作用 |
|---|---|
| `comic/flux2.py::build_flux2_pose_workflow` | 构造 API 格式工作流（13 主干节点 + N×4 人物链 + 4 姿势链） |
| `comic/flux2.py::ensure_flux2_pose_workflow` | 落盘到 ComfyUI `user/default/workflows/aibar_flux2_pose_consistent.json`（**API 格式**，供 AIBAR runner 直接 POST `/prompt`，不是给编辑器侧栏打开的 UI 格式——与 M14 `ensure_pose_workflow` 同款） |
| `comic/flux2.py::_add_reference` | 单条参考链构造（LoadImage→VAEEncode→ReferenceLatent×2），两个 builder 共用 |
| `tests/py/test_comic_flux2.py` | 21 项单测（含 8 项 M17.3） |

#### 三个「人物一致」杠杆

Klein 的 `ReferenceLatent` **没有权重/强度参数**（`/object_info` 实测确认：
`input` 只有 `conditioning` + `optional.latent`）。所以「这张参考图有多重要」
**只能用重复次数表达**：

| 杠杆 | 做法 | 代价 |
|---|---|---|
| ① 多张人设图 | `character_images=[a, b, c]`（最多 3 张，`MAX_CHARACTER_REFS`） | 每张多 4 个节点，注意力被参考图分摊 |
| ② 同一张重复加权 | `character_images=[a, a, a]` → a 的权重 ×3 | 同上；超过 3 条链后出图会「贴」参考图，失去变化 |
| ③ 固定 seed | `seed=12345`（或 `comic.actors.actor_seed(actor, randomize=False)`） | 无；但换姿势时也要保持同一 seed，否则人物会漂 |

> ⚠️ 三者要**同时**用。只固定 seed 不给人设图 → 人物照样漂；
> 只给人设图不固定 seed → 脸会在几张之间抖。

#### 工作流构造

```python
from comic.flux2 import build_flux2_pose_workflow, ensure_flux2_pose_workflow

graph = build_flux2_pose_workflow(
    character_images=["char_a.png", "char_a.png"],  # 同一张重复 = 加权 ×2
    pose_image="pose_0001.png",                      # 姿势/结构参考
    positive="1girl, long white hair, blue eyes, white dress, anime style",
    negative="lowres, bad anatomy, blurry, watermark",
    seed=12345,          # 跨帧固定 → 人物一致
    steps=4, cfg=1.0, width=1024, height=1024,
)

# 或落盘成 ComfyUI 工作流文件（幂等；参数全空时会自动扫 input/ 下前两张 PNG）
ensure_flux2_pose_workflow(["char_a.png"], "pose_0001.png", positive="...")
```

#### 节点 ID 分配

| 节点 ID | 内容 |
|---|---|
| 1-5, 14-21 | 主干（模型加载 / 提示词 / latent / 采样 / 解码 / 保存），与 §4.13 完全一致 |
| 100, 104, 108… | 人物参考链（`CHARACTER_REF_ID_BASE=100`，步长 4；第 n 条链占 `100+4n` ~ `100+4n+3`） |
| 最后 4 个 id | 姿势链（接在所有人物链之后，保证「先锁人、后锁姿势」） |

> 人物链从 100 起是为了**避让** `build_flux2_workflow` 的 6-13，两套图不冲突。

#### ⚠️ 实测结论：姿势参考基本无效（2026-09-08）

同人设（`aibar_char_ref.png` ×2）+ 同 seed（12345）+ 同提示词，只换姿势图，
1024×1024 / 4 步 / CFG 1.0 出图，做像素级比对（MAD = 平均绝对差，越大越不同）：

| 对比 | 输入图差异 | **出图差异** | >16 灰阶像素占比 | 判定 |
|---|---|---|---|---|
| 骨架 A vs 骨架 B | 5.73 | **1.97** | 3.3% | ❌ 输出差 ≪ 输入差，姿势没被跟随 |
| 真实帧 A vs 真实帧 B | 25.98 | **3.33** | 2.6% | ❌ 输入差 26、输出只差 3.3，同样没跟随 |
| 有骨架 vs 无骨架 | — | 9.67 | 11.5% | ⚠️ 只是"多一条参考链"的整体扰动 |
| 骨架 vs 真实帧（都当姿势参考） | 52.63 | 66.73 | 89.4% | ⚠️ 整张图被拖向那张照片 |

与人设参考图的**平均色差**（越小越像本人）：

| 姿势参考 | 平均色差 | 人物一致性 |
|---|---|---|
| 骨架 A / 骨架 B / 无姿势 | 1.34 / 1.36 / 1.24 | ✅ 保住 |
| 真实帧 A / 真实帧 B | **60.57 / 59.47** | ❌ 丢失 |

**两条结论**：

1. `ReferenceLatent` 是**外观 / 整体构图迁移**机制，**不是** ControlNet。姿势参考
   基本被忽略——输出差异远小于输入差异，说明模型没在跟随动作。
2. **用真实照片当姿势参考比用骨架更糟**：出图被整体拖向那张照片，人物一致性
   同时丢失（色差 1.3 → 60）。用骨架至少保得住人物，代价只是姿势无效。

**怎么办**：

- 要**严格姿势控制** → 走 **M14**（SDXL + ControlNet-Union openpose + IPAdapter FaceID），
  真 ControlNet，骨架图原样吃。这是唯一有效的路。
- 要**同一个人物的稳定续写 / 分镜** → 用本工作流，`pose_image` 留空或只放**同风格**
  的构图参考，别指望它摆姿势。
- 别用真实照片当姿势参考「以为能控姿势」——它只会把人换掉。

### 4.15 SDXL + ControlNet-Union openpose 姿势工作流（M14 链路，2026-09-08 复核）

> **要严格姿势控制就用这条**。它是**真 ControlNet**（骨架图作为结构条件注入 UNet），
> 不是 §4.14 那种靠注意力迁移的软参考。已实测：同一对骨架输入，SDXL 出图差异
> **50.28**（72.8% 像素变化），Klein 只有 **1.97**——差一个数量级。

#### 两个变体

| 变体 | 文件名 | 节点数 | 用途 |
|---|---|---|---|
| 锁脸 + 控姿 | `aibar_pose_consistent.json` | 15 | 既要是这个人、又要这个姿势 |
| **纯 openpose 控姿** | `aibar_pose_openpose.json` | 11 | 只要姿势，不锁脸 |

纯 openpose 版 = 参考图留空 → `build_pose_workflow` 自动跳过整条 IPAdapter 链
（省掉 `CLIPVisionLoader` / `IPAdapterUnifiedLoaderFaceID` / `IPAdapterFaceID` 三个节点
和一次 insightface 人脸检测）。

#### 构造

```python
from comic.pose import build_pose_workflow, ensure_pose_workflow, POSE_OPENPOSE_FILENAME

# A. 锁脸 + 控姿
graph = build_pose_workflow(
    reference_image="aibar_poses/actor_ref.png",  # 锁脸（留空=跳过 IPAdapter）
    pose_image="aibar_poses/pose_0000.png",        # 控姿（骨架图）
    positive="1girl, long hair, blue eyes, white dress, anime style",
    negative="lowres, bad anatomy, blurry, watermark",
    seed=12345, controlnet_strength=0.9,
)

# B. 落盘纯 openpose 版 —— 必须 auto_fill=False！
ensure_pose_workflow(
    pose_image="aibar_poses/pose_0000.png",
    filename=POSE_OPENPOSE_FILENAME,
    auto_fill=False,   # ⚠️ 不关会被自动扫描补上参考图，落出来还是 15 节点锁脸版
)
```

> ⚠️ **`auto_fill` 是个坑**（实现时踩到）：`ensure_pose_workflow` 默认会在图像留空时
> 自动扫 `input/aibar_poses/` 补齐。想落「纯控姿」版时，留空 `reference_image` **不够**——
> 扫描会把第一张 `actor_*.png` 补进来。必须显式 `auto_fill=False`。

#### 界面入口：工作流页 →「生成姿势工作流」

不必写代码。**工作流**页面右上角有「生成姿势工作流」按钮，弹窗里选：

| 选项 | 说明 |
|---|---|
| 工作流变体 | `锁脸 + 控姿（15 节点）` / `纯 openpose 控姿（11 节点）`；切到后者会隐藏参考图选项 |
| 参考图（锁脸） | 从 `input/aibar_poses/` 下的 `actor_*` / `ref_*` / `face_*` 里选 |
| 骨架图（控姿） | 从 `pose_*` 里选，**默认选第一张** |
| 正/负提示词 | 可留空 |

生成后会 toast 提示文件名与节点数，并**自动同步一次**让新工作流出现在列表里。

> ⚠️ **骨架图别留空**：`auto_fill=False` 会同时关掉「补参考图」和「补骨架」，两张都空会
> 落出 **7 节点裸版**（既无 IPAdapter 也无 ControlNet = 不能控姿）。路由层已兜底——
> 纯 openpose 变体下没选骨架会自动挑第一张 `pose_*.png`；一张骨架都没有时才会退化，
> 此时弹窗会给出黄色警告，请先到「动作帧」页面生成预置姿势库。

| 6 / 7 / 8 | `LoadImage(骨架)` / `ControlNetLoader` / `SetUnionControlNetType` | 控姿链，`type=openpose` |

| 12-15 | `EmptyLatentImage` / `KSampler` / `VAEDecode` / `SaveImage` | 出图 896×1152 / 28 步 / CFG 6.5 |

#### 素材目录约定

图像要放在 `ComfyUI/input/aibar_poses/`（`POSE_SUBDIR`）：

- 参考图按 `actor_*.png` / `ref_*.png` / `face_*.png` 命名，自动扫描才会优先选中；
- 骨架图按 `pose_*.png` 命名；`ensure_pose_library()` 会生成 20+ 种预置骨架
  （站 / 走 / 跑 / 跳 / 跪 / 挥手 / 拔刀 …）。

#### 排障

| 现象 | 处理 |
|---|---|
| 落盘出来还是 15 节点锁脸版 | 没传 `auto_fill=False`，见上 |
| 想换 ControlNet 类型（canny/depth） | 改 `SetUnionControlNetType` 的 `type`（`openpose` / `canny` / `depth`），骨架图换成对应预处理图 |
| 姿势跟得不够紧 | 调大 `controlnet_strength`（默认 0.9）；过大会出图发糊 |
| 脸不像 | 调 `ipadapter_weight` / `faceidv2_weight`（均默认 0.85）；参考图必须是**能检出人脸**的正脸图 |
| `IPAdapterFaceID` 报人脸检测失败 | insightface 没检出脸。换正脸参考图；或只要姿势就改落纯 openpose 版 |

> ⚠️ **校验姿势别指望 DWPose 反向抽骨架**：实测 DWPose（`yolox_l.onnx`，真实人像训练）
> 在本项目动漫风出图上**完全检不出人**——连参考图本身都抽不出骨架（全黑）。
> 想自动校验得换检测器或改用人像照片；当前只能肉眼判。

## 5. 常见操作与排障

| 现象 | 原因 / 处理 |
|---|---|
| 页面提示 ComfyUI「已停止」 | ComfyUI 未运行或端口不通；`/api/comfyui/status` 返回 `running:false`，属正常降级，不影响其他模块。`./scripts/up.sh status` 查状态，`start` 拉起。 |
| 改了 Python 不生效 | AIBAR 无 reloader，需 `./scripts/up.sh restart --force`。 |
| 端口被占用无法启动 | 默认不杀占用者；确认后 `restart --force` 强制清理（会结束该端口占用进程，谨慎）。 |
| 反推一直转圈 | 用异步模式（`async:true`），前端按真实 `stage` 轮询；若服务重启过残留任务，首次读取会判死为 `failed` + `interrupted`，可重试。 |
| 高级 Provider（Qwen3-VL/JoyCaption）不可用 | Qwen3-VL 需先 `scripts/install_providers.py --download`；JoyCaption 仓库 gated，需 `HF_TOKEN` 后单独 `install --provider comfyui_joycaption_beta`。 |
| 上传被拒 415 | 非图片 / 动画 / 损坏 / 超 20MB；确认文件为 png/jpg/jpeg/webp 且为真实静态图。 |
| 日志里看不到提示词内容 | 符合隐私规范：日志只记 ID / `media_type` / `provider` / `stage` / `duration_ms` 等，不记正文与密钥。 |

## 6. 关闭与重启

```bash
./scripts/up.sh stop     # 停止
./scripts/up.sh restart  # 重启（改 Python 用 restart --force）
```

重启时若改动了 ComfyUI 桥梁扩展，需 `restart` 让 ComfyUI 重新加载 `custom_nodes/AIBAR-Bridge`。
