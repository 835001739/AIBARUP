> 本文是 AIBAR（本机 AI 绘画工作流管理与提示词资产平台）的需求基线。

## 1. 产品定位

AIBAR 是一套**纯本机**运行的 AI 绘画辅助平台，向上连接本机 ComfyUI（默认 :8188），向下沉淀工作流 / 图库 / 模型 / 提示词资产，提供一个统一、暗色、工作室式的操作界面。它不依赖任何云服务即可完成：

- 自动同步 ComfyUI 的工作流、产出图、模型清单；
- 提示词结构化扩写（保守 / 均衡 / 创意三档）；
- 多模态精品提示词库（图片 / 视频 / 歌曲三类资产的片段化词条）的浏览、检索、收藏与自动学习；
- 图片 → 提示词「反推」（从 ComfyUI 产出图 / 用户上传图中恢复可复用的提示词）；
- Provider 中心：本地 BLIP、本地 Qwen3-VL（8B/4B）、JoyCaption、外部 OpenAI 兼容视觉接口的自动发现、自检与降级。

**目标用户**：本地部署 ComfyUI 的 AI 绘画创作者 / 工程师，需要把散落在工作流与成图里的提示词沉淀为可检索、可复用、可扩写的资产。

## 3. 技术约束（来自 `HARNESS.md`）

| 层 | 选型 | 约束 |
|---|---|---|
| 语言 | Python 3.13 | 隔离 venv：`.venv` |
| Web | Flask | 使用 **Blueprint** 分模块，禁止把所有路由堆在 `app.py` |
| 前端 | 原生 HTML/CSS/JS | **无构建步骤**，不引入前端框架 |
| 存储 | SQLite（标准库 `sqlite3`） | 迁移必须幂等 |
| 图像 | Pillow | 读取 PNG 内嵌文本块 |
| 配置 | `.env` + `python-dotenv` | 只通过 `config.Config` 读取，业务包不得直接读环境变量 |

**统一 API 契约**：成功 `{"ok":true,"data":...}`；失败 `{"ok":false,"error":{"code":"...","message":"..."}}`。错误码英文下划线（`invalid_input` / `not_found` / `provider_offline` 等）。

**隐私硬性约束**：日志与 API 响应中**禁止**出现提示词正文、图片内容、API Key、完整外部 endpoint、本机绝对路径；只允许记录 ID、`media_type`、`dimension`、`provider`、`profile`、`intensity`、`stage`、`status`、`error_code`、`duration_ms`、输入输出长度、图片字节数与尺寸。

**依赖方向（单向）**：`config/core` ← `sync`/`prompt`/`promptlib` ← `reverse`；业务包之间不得互相 import。

## 4. 模块需求（M1–M11）

> 说明：当前实现覆盖 **M1–M4、M6–M11、M12、M13、M14 共 13 个模块**；PRD 原始编号中 **M5 预留未实现**，故按实际落地模块描述。

### M1 · ComfyUI 联动（探测与状态）

- **职责**：实时探测本机 ComfyUI 运行状态，供全站判断联动能力；ComfyUI 不可用时不抛异常、仅降级显示「已停止」。
- **功能点**
  - 探测 8188 端口存活、设备（mps/cuda/cpu）、显存、启动参数；
  - 后台拉起 ComfyUI（`POST /api/comfyui/start`）；
  - 全站概览 `GET /api/status`（ComfyUI 状态、各资源计数、上次同步时间、自动同步开关与间隔）。
- **验收标准**：ComfyUI 停止时上述接口返回 `running:false` 而非 500；`/api/status` 不依赖 ComfyUI 可达。

### M2 · 工作流管理

- **职责**：把 ComfyUI `user/default/workflows` 下的工作流同步进 AIBAR，解析为可浏览的结构化卡片；支持「点击工作流 → 衔接 ComfyUI 直接出图」。
- **功能点**
  - 列表：名称、节点数、节点类型、正 / 负提示词预览、同步时间（`GET /api/workflows`）；
  - 详情：节点清单、正 / 负提示词全文（`GET /api/workflows/<filename>/detail`）；
  - 下载原始 JSON（`GET /download/workflow/<filename>`）；
  - **增强（用户新增需求，已验收）**：工作流卡片「用 ComfyUI 出图」——AIBAR 把 UI 格式工作流转 API prompt 图 → `POST /prompt` 交 ComfyUI 生成 → 抽屉内轮询 `history` 并同源代理 `/view` 渲染产出图；「在 ComfyUI 编辑器中打开」深链。
- **验收标准**：UI→API 转换复用 `/object_info` 判定挂件与连线；出图过程零前端报错；深链不泄露 `root:` 等目录外内容（路径穿越已修）。

### M3 · 图库

- **职责**：同步 ComfyUI 产出图，提供分页浏览、灯箱详情与图片 → 工作流溯源。
- **功能点**
  - 分页列表：`{items,total,page,page_size}`，含尺寸、字节、提示词、工作流链接（`GET /api/gallery`）；
  - 灯箱详情：`GET /api/gallery/<id>` 完整元数据；
  - 图片 → 工作流溯源：`GET /api/gallery/<id>/workflow`。
- **验收标准**：分页上限 100，超出有翻页而非静默截断；静态图经 `/static/gallery/<path>` 可访问。

### M4 · 同步引擎与日志

- **职责**：后台增量同步工作流 / 图库 / 模型，派生可复用案例；记录同步日志。
- **功能点**
  - 立即同步一次（`POST /api/sync/now`）返回本次增量；
  - 切换自动同步（`POST /api/sync/auto`）；
  - 同步日志：`GET /api/logs`（`{items:[{id,ts,type,message,status}]}`）。
- **验收标准**：首扫导入 25 工作流 / 1858 图 / 61 模型，派生 1794 案例；`auto_sync=true`、10s 轮询；增量基于内容哈希，幂等不重复。

### M6 · 提示词工作台（扩写引擎）

- **职责**：基于模型档案（profile）做确定性的提示词结构化扩写，支持 rules 引擎与外部 Provider 降级。
- **功能点**
  - 档案 / 维度 / 模板查询（`GET /api/prompt-library`）；
  - 扩写：`POST /api/prompts/expand`，入参 `{original_prompt, profile, intensity, template_id, options, provider}`，返回原始 + 扩写正负向 + 分维度段落 + 新增说明 + 警告 + 耗时；
  - 历史：保存 / 列表 / 删除 / 收藏（`/api/prompts/history`）。
- **验收标准**：空输入 / 仅标点 / 超 2000 字符 / 未知 `intensity` → `400 invalid_input`；rules 模式同输入同输出（确定性）；重复 / 互斥词消除或告警；外部 Provider 失败回退 rules，日志仅记 profile/provider/duration_ms。

### M7 · 多模态精品提示词库

- **职责**：图片 / 视频 / 歌曲三类资产的片段化词条库，支持渐进分面筛选、搜索、收藏、排序、回填，以及生成后自动学习入库。
- **功能点**
  - 分面：`GET /api/prompt-library/facets`，仅返回当前筛选条件下仍有数据的层级与数量（无空层级）；
  - 词条列表：多维筛选 + 分页（`GET /api/prompt-library/entries`）；
  - 词条写操作：新增 / 编辑 / 删除 / 记录使用 / 收藏（`POST/PATCH/DELETE/use/favorite`）；
  - 候选审核：低置信度生成进候选，人工通过 / 拒绝（`/api/prompt-library/candidates`）。
- **验收标准**：点击词条光标插入、去重、可撤销、不自动触发扩写、使用统计（`use_count`）更新；内置词条删除表现为本地隐藏并写入忽略指纹；空泛 / 连接词 / 整段不入库（种子 ≥150 门槛，实测 154 条）；高置信度自动入库、低置信度进候选、已存在 / 拒绝 / 失败正确处理（🟡 待端到端走查）。

### M8 · 暗色工作室 UI

- **职责**：统一的六页导航 + 中央画布的工作室外壳，承载 M6/M7/M9 的子视图。
- **功能点**：导航项 提示词工作台 / 工作流 / 画廊 / 案例库 / 模型 / 同步日志；设计令牌（颜色 / 间距 / 字体）；响应式断点；键盘可达。
- **验收标准**：全站暗色规范一致；六页导航可切换；反推「选图 → 分析 → 编辑 → 回填 → 保存」闭环在浏览器中可用（🟡 待人工走查）。

### M9 · 图片提示词反推

- **职责**：从图片恢复提示词，来源清晰（原始元数据 / 视觉模型）、结果可编辑、可入库，含隐私与去重闭环。
- **功能点**
  - 上传：`POST /api/prompt-reverse/uploads`（multipart，仅 png/jpg/jpeg/webp，≤20MB，校验真实图片内容；动画 / 损坏 → `415 invalid_image`）；
  - 创建任务：`POST /api/prompt-reverse/jobs`（同步 `async:false` 返回完整结果 / 异步 `async:true` 返回 202 待处理任务，前端轮询真实阶段）；
  - 任务读取 / 取消 / 保存编辑 / 入库（`GET /jobs/<id>`、`cancel`、`result`、`save`）；
  - 历史与删除：`GET/DELETE /api/prompt-reverse/history`；Provider 列表与外发确认。
- **验收标准**：来源 `metadata`（原始提示词恢复）或 `vision`（视觉模型）；结果分段、可编辑、可勾选入词库；`async:true` 下进度来自后端真实 `stage` 而非假进度条；服务重启残留任务判死为 `failed` + `error_code:"interrupted"`；入库幂等（inserted/merged/candidates/discarded）。

### M10 · Provider 中心（本地）

- **职责**：自动发现本机可用视觉 Provider，无 .env / 无 Key 即可基础反推。
- **功能点**：Provider 列表（`GET /api/prompt-reverse/providers`，不返回密钥 / 完整 endpoint）；刷新探测；分层测试；设置默认。
- **验收标准**：`comfyui_blip` 基于 ComfyUI + ImagePromptInterrogator + BLIP 自动识别为 `ready`；状态枚举 `ready|unconfigured|offline|missing_node|missing_model|missing_mmproj|incompatible_runtime|out_of_memory|unauthorized|error`。

### M11 · Provider 中心（高级 / 外部）

- **职责**：本地高级 VLM（Qwen3-VL 8B/4B、JoyCaption）与外部 OpenAI 兼容视觉接口的接入、自检与降级。
- **功能点**：同 M10 接口；高级模型经 `AILab_QwenVL_GGUF` 节点契约提交；外部 Provider 需用户外发确认（`consent`）。
- **验收标准**：Qwen3-VL 8B/4B GGUF + mmproj 下载完成并真实冒烟（8B 合成图 → 结构化 JSON，18s）；指令经 `custom_prompt` 注入；JoyCaption 仓库 gated，需 `HF_TOKEN` 后单独安装；外部 Provider 失败不影响其他模块。

### M12 · 漫画工作室（大工作流 / ComfyUI 出图队列）

- **职责**：维护「生产漫画」的大工作流（Big Workflow），把零散的章节、分镜、预制提示词与出图工作流组织为可管理的层级资产，并通过与 ComfyUI 对接的**出图队列**把预制提示词真正变成成图；大工作流完成后，仍可对单张分镜图**重新生成**。
- **层级模型**：`漫画项目（project）→ 章节（chapter）→ 分镜页（page）`；项目聚合多章节，章节聚合多分镜页；每页携带一张预制提示词 + 出图工作流 + 随机种子。
- **功能点**
  - **漫画概览**：`GET /api/comic/projects` 返回项目卡片网格，含每项目聚合的章节数 / 分镜页数 / 已完成页数（status=`done` 的 page 计数），支持按状态（草稿 `draft` / 制作中 `production` / 完成 `done`）筛选。
  - **项目 CRUD**：`GET/POST /api/comic/projects`、`GET/PATCH/DELETE /api/comic/projects/<id>`；删除项目级联删除其下所有章节与分镜页（含关联 job）。
  - **章节管理**：`GET/POST /api/comic/projects/<id>/chapters`、`PATCH/DELETE /api/comic/chapters/<id>`；章节含标题、序号（`order_idx`）、摘要（`summary`）、状态。
  - **分镜预制提示词 + 出图工作流**：`GET/POST /api/comic/chapters/<id>/pages`、`PATCH/DELETE /api/comic/pages/<id>`；每页字段：`prompt_text`（正向预制提示词）、`negative_text`（负向）、`workflow_filename`（关联 ComfyUI UI 工作流文件名，来自 M2 同步）、`seed`（随机种子）、`status`（pending/queued/generating/done/failed）。
  - **ComfyUI 出图队列**：
    - 单页出图 `POST /api/comic/pages/<id>/generate`：把该页预制提示词注入关联工作流 `workflow_filename`（经 `sync.workflow_convert.convert_text` 转 API prompt 图），入队 `comic_jobs` 后由后台 worker 提交 ComfyUI `POST /prompt` 生成，轮询 `history` 并下载首张成图，落盘到 `data/comic_outputs/<project>/<chapter>/<page>_<hash>.png`（库内仅存相对路径）。
    - 单页重生成 `POST /api/comic/pages/<id>/regenerate`：大工作流完成后，对任意一张分镜图按当前预制提示词（可先编辑）**重新出图**，无视其当前状态。
    - 整章出图 `POST /api/comic/chapters/<id>/generate`、整本出图 `POST /api/comic/projects/<id>/generate`：批量把 `status≠done`（或指定）的页入队。
    - 队列查看 `GET /api/comic/jobs`（按 `project_id` / `status` 过滤）；`POST /api/comic/jobs/<id>/cancel` 取消排队中任务并把对应页重置回 `pending`。
  - **产出图访问**：`GET /api/comic/output/<path:rel>` 经 `safe_join` 同源代理 `data/comic_outputs/` 下成图（路径穿越已防护，缺失返回 404）。
  - **前端能力**：`static/js/comic.js` 实现概览网格、项目/章节/分镜三级下钻、通用表单弹窗（新建/编辑项目/章节/页）、分镜列表每张图的预览与「生成/重生成/编辑/删除」、队列表格与活跃任务 4s 轮询。
  - **Skill 流程导入（可复用能力）**：`POST /api/comic/import-skill` 把任意 `SKILL.md` 的「流程」沉淀为漫画大工作流，实现「任意 skill → 本项目能力」的复用：
    - 映射规则：`frontmatter.name` → 项目名（导入时可用 `title` 覆盖）；`## 段落` → 章节；段落内编号步骤（`1. …` / `2. …`）→ 分镜页（`prompt_text` = 步骤原文，出图前可在页内编辑为真正的图像提示词）；段落无编号步骤则整段作为单页 `prompt_text`。
    - 说明性段落自动跳过、不建章节：`When to use` / `前置条件` / `Pitfalls`（含「Pitfalls（…）」这类带括号变体）/ `Verification` / `Files`（大小写不敏感、兼容中英文括号后缀）。
    - 出图工作流：导入时若指定 `workflow_filename` 则复用；否则自动把一份 **FLUX.2 Klein 4B 最小化 13 节点工作流**（`flux2_storyboard_aibar.json`，API 格式，已适配 `RandomNoise.noise_seed` 注入）写入 ComfyUI 工作流目录并设为项目 `default_workflow` 与各页 `workflow_filename`，使导入即得可出图能力（不依赖 ComfyUI 在线）。
    - 入参二选一：请求体 `markdown`（直接粘贴 SKILL.md 全文）或 `path`（本地 SKILL.md 路径，优先用 `markdown`）；返回新建 `project_id / project_name / workflow_filename / chapters / pages`。
  - **分镜工作流（世界观 + 剧情摘要 → 自动分集出图）**：`POST /api/comic/projects/<id>/storyboard` 把项目的「世界观 / 剧情摘要」一键转为分镜大工作流：
    - 数据层：`comic_projects` 新增可编辑字段 `worldview`（世界观）、`plot_summary`（剧情摘要）、`pages_per_chapter`（出图数量 / 每章页数，int 默认 1、范围 1~12）与 `style_preset`（出图风格，text 默认 `none`），由 `core/db.py._COLUMN_MIGRATIONS` 幂等补列，启动时自动迁移。
    - 前端入口：项目详情页「分镜工作流」面板提供两个可编辑文本框（世界观 / 剧情摘要）、一个「出图数量（每章页数）」数字输入（1~12）与一个「出图风格」下拉（清单取自 `GET /api/comic/style-presets`），可「保存设定」一并写回项目，或「自动生成分镜出图」按当前内容一键生成；项目工具栏另有「自动分镜」按钮可基于已存字段重复生成。
    - 分集拆分（确定性、可离线）：剧情摘要按「第N集 / 第N话 / EPn / 数字.数字 / （数字）」标记或空行分段；单段落内联编号（「1. a 2. b」）也拆分；无标记则整体作一集（上限 24）。
    - **出图数量（每章页数）**：每集剧情按 `pages_per_chapter` 转换为对应数量的画面描述 —— 按句切分（句数足够则均匀取样覆盖首尾；句数不足则**循环取句** `sentences[i % len]`，而不是反复复用末句）并按页序轮换镜头景别（远景，建立镜头 / 中景 / 近景 / 特写 / 过肩 / 俯仰角度 / 动态镜头 / 空镜），保证每页提示词独立不雷同；每集 → 一个章节 + N 张分镜页。景别单独落库到 `comic_pages.shot_note` 并展示在分镜页卡片上。
    - **出图风格（风格统一，本次新增）**：可选 `none`（不限制）/ `japanese_manga`（日式黑白漫画）/ `shinkai`（新海诚动画电影风）/ `american_comic`（美式漫画）/ `ink_wash`（国风水墨）/ `watercolor`（水彩绘本）/ `cyberpunk`（赛博朋克）/ `pixel_art`（像素游戏风）/ `realistic`（写实厚涂插画）。生成时对**每一集拆分出的每一页**都执行同一个 `styles.apply_style`：正面提示词末尾追加**完全相同**的一段风格描述词，负面提示词合并同一套排除项，从而**保证每一集的图片风格统一**；非法取值不写回项目（保留原值），大小写/空格容错，追加幂等，超长截断优先保留风格词。
    - 每分镜页：其画面描述经 `prompt.providers.expand`（规则引擎优先、`AI_PROVIDER_*` 启用时可选 LLM）扩写为图片提示词，再按出图风格规范后写入页 `prompt_text`/`negative_text` 并自动入队。
    - 零配置出图：项目未设 `default_workflow` 时，自动写入 FLUX.2 最小化工作流并设为默认，使分镜页无需手动指定即经 ComfyUI 出图（与 Skill 导入一致）。
    - AI 降级：LLM 拆分或扩写失败一律回退规则引擎，整体不失败。
    - **人物一致性（角色卡 / 人物锚点，本次新增）**：新增 `comic_characters` 表（角色卡：`name` / `aliases` / `appearance` / `outfit` / `palette` / `negative` / `seed_offset`，单项目上限 12）与 `comic_projects.base_seed`（基准种子）。
      - 角色抽取（`comic/characters.py::extract_candidates`，纯规则可离线）：称谓词典 + 「XX说/道/问」式人名捕获 + 英文人名 + 「称谓 + 人名」组合捕获；后处理剥离粘连的动词与称谓前缀（`阿岚说`→`阿岚`、`少女苏叶`→`苏叶`），用非人名黑名单词典拦掉「骑士沉默不语」类误抽取，已被完整人名吸收的裸称谓不再单独成角；抽取只**新增**缺失角色，绝不覆盖用户手填内容。
      - 锚点注入：`build_character_anchor` 按固定顺序（名字→外貌→服装→配色）拼装，同一角色在任何一页得到**逐字相同**的锚点；生成分镜时插到提示词最前（模型对靠前描述权重更高），角色「排除项」并入负面提示词。
      - 确定性种子：`derive_seed(base_seed, project_id, chapter_id, page_idx, anchor_key(hits))` —— 同一角色组合在同一位置永远得到同一颗种子，跨页不雷同、重跑可复现。
      - **主角贯穿（本次新增）**：角色卡新增 `is_main`（首张卡默认主角，可随时通过「设为主角 / 取消主角」切换）。分镜页的角色命中改为 `select_page_characters(text, characters)` = **文本命中 ∪ 主角**，即使某页剧情里没提到主角的名字，主角的锚点仍然注入该页 —— 解决「主角在过场页脸变了」的问题。界面上主角卡带 `主角 · 贯穿全本` 徽标。
      - **角色候选排序（本次新增）**：抽取结果按「出现频次 → **首次出场位置** → 长度 → 字典序」排序，同频次时先登场的排第一（= 默认主角），避免称谓词（如「引路人」）因匹配规则多而挤掉真正的第一主角（如「阿岚」）。
    - **ComfyUI 衔接增强（本次新增）**：
      - 出图体检 `GET /projects/<id>/precheck`：`comic/diagnostics.py` 检查 ComfyUI 在线（含耗时）、工作流文件是否存在及其节点数、节点是否齐全、队列是否拥堵，输出中文 `hints` 建议；所有网络调用失败一律降级为「离线」，绝不抛到路由层。
      - 失败重试（`comic/runner.py`）：可重试错误码（`comfyui_offline` / `comfyui_timeout` / `submit_failed` / `wait_failed` / `timeout` / `download_failed`）按退避策略重排，最多 `MAX_ATTEMPTS=3` 次；重试期间任务回到 `queued` + `stage='retry_wait'` + `next_retry_at`，worker 只捞到期任务。
      - 可读错误：`diagnostics.human_error` 把错误码翻译成中文，同时写入 `comic_jobs.error_message` 与 `comic_pages.error_message`，界面不再出现裸英文报错。
      - 单页深链 `GET /pages/<id>/editor-link`：用该页提示词 + 排除项 + 工作流在 ComfyUI 中直接载入，便于手工微调后出图。
    - **工作进度展示（本次新增）**：`service.project_progress` 聚合各状态页数、完成百分比、章节级进度、当前生成中页、最近失败原因与失败原因分布；`GET /projects/<id>/progress` 附带 ComfyUI 在线探测。前端「出图进度」卡每 3 秒**局部**刷新（只重画进度/章节/队列，不重建整页，不打断正在编辑的输入），并展示分集进度条与中文失败原因。
      - **剩余时间预估（本次新增）**：`_avg_job_seconds(project_id, sample=5)` 取最近 5 条已完成任务的实际耗时均值（忽略 ≤0 与 ≥3600s 的异常样本），`project_progress` 额外输出 `avg_job_seconds` 与 `eta_seconds = 均速 × (排队数 + 正在出图的 1 张)`；前端在「有排队或正在出图」时显示「预计还需 X（按最近出图均速 Y/张估算）」，无历史样本时不显示（返回 0）而不猜。
    - **分镜页提示词可重建（本次新增）**：每页在落库最终提示词的同时，保留**未注入角色锚点、未追加风格词之前**的原始素材 `base_prompt`（扩写后的画面描述）、`base_negative`、`shot_note`（景别）。
    - **提示词重刷（本次新增）**：`POST /projects/<id>/refresh-prompts`（`storyboard.refresh_project_prompts`，参数 `style` 可选、`requeue` ∈ `failed`/`all`/`none`）。改完角色卡外貌/服装/配色、或想整本换风格时，不必重拆剧情、不必重建章节，只重跑「锚点注入 + 景别 + 风格 + 种子」这一层装配：
      - 遍历项目全部分镜页，用页上存的 `base_prompt` 重算 `prompt_text` / `negative_text` / `seed`（与首次生成走**同一个** `compose_page_texts` 纯函数，因此不会产生两套逻辑漂移）；
      - **幂等**：没改任何角色卡时再刷一次，`changed = 0`，提示词与种子逐字不变；
      - **兜底**：历史页没有 `base_prompt`（本次改造前生成的）时回退用 `prompt_text` 当原料，老项目同样可刷；
      - 重刷后按 `requeue` 决定重排范围：默认 `failed` 只重跑失败页（推荐，不浪费已完成图），`all` 全部重出，`none` 只改提示词先不出图。
    - **分镜重建模式（本次新增）**：`POST /projects/<id>/storyboard` 增 `mode` ∈ `append`（默认，追加新章节）/`rebuild`（重建）。反复生成会叠加出多个「第1集」，重建模式先级联删除全部旧章节（连带分镜页与 job），再按当前世界观/剧情/风格重新生成，返回 `removed_chapters`；前端生成弹窗下拉选择，并实时提示两种模式的差别。
    - **出图产物加固（本次新增）**：`runner._inject_prompt` 对正/负向文本节点做**三层识别**（节点 title 含 negative 关键词 → 节点内容本身像负面词 → 位置兜底），不再依赖「第 1 个节点是正向、第 2 个是负向」的脆弱假设，自定义工作流也能正确注入；`_save_output` 写新图前先删除该页的旧产出文件（`{page_id}_*.png`），避免同一页重出图后目录里堆一串行号文件、磁盘越用越满。
    - **产出图回流图库（F1，本轮新增）**：漫画产出图原本只落 `data/comic_outputs`，不进图库，导致 M9「反推提示词」与图库溯源对漫画页不可用。`comic/runner.py` 出图成功后将成图经 `sync.scanner.register_image` 注册进 `images` 表（内容 sha256 去重、幂等、落 `static/gallery` 副本），并写回分镜页 `image_id`；`comic/service.py::sync_gallery` 提供补跑入口（`POST /projects/<id>/sync-gallery` 单项目、`POST /sync-gallery` 全项目），对「已出图但图库空缺」的页补齐，对「产出文件已被 ComfyUI 移走」的页清空悬空 `image_path`/`image_id`（不让卡片裂图）。回流后已完成页出现「反推提示词」按钮（复用图库深链送进 M9）。
    - **单页重扩写（F3，本轮新增）**：新增 `POST /pages/<id>/reexpand`，用分镜页 `beat_text`（分镜工作流落库的剧情原文）重新扩写并经 `compose_page_texts` 按当前角色锚点 / 风格重组成图提示词；无 `beat_text` 时跳过扩写、`provider=skip` 仅重排并给 `warnings`。`requeue=true` 顺带重入队出图。前端每页「重扩写」按钮触发；与「重刷提示词」共用同一纯函数，不漂移。
    - **按条件批量重出图（F4，本轮新增）**：项目工具栏「按条件重出」弹窗，按范围（全部页 / 只重跑失败的 / 只跑还没出图的）批量入队，实时显示各范围页数；`api()` 解包后传 `data.items` 给弹窗（修复误传响应体导致 `forEach is not a function` 的浏览器崩溃）。
- **验收标准**：
  - 创建项目→章节→分镜页（含预制提示词 + 工作流文件名 + 种子）链路 200；分镜页字段正确落库。
  - 单页 `generate` 入队后 `comic_jobs` 出现 `status=queued`，worker 拉起后提交 ComfyUI 并在成图后写回 page `status=done` + 相对产出图路径（🟡 需 ComfyUI 真实可达 + 工作流含 SaveImage 节点，待端到端走查）。
  - 大工作流完成后 `regenerate` 对任意页（含 `done`）可再次出图，复用/更新预制提示词，不破坏其他页。
  - 删除章节/项目级联清理分镜页与 job；`cancel` 仅重置排队中页、不影响已 `done` 页。
  - 路径穿越（`/api/comic/output/..%2f...`）被 `safe_join` 拒绝，缺失文件返回 404，不泄露目录外内容。
  - 分镜工作流：填写世界观/剧情摘要（与出图数量 / 出图风格）→ 一键生成后，章节数 = 集数、每章分镜页数 = 出图数量、全部入队 `queued`；`worldview`/`plot_summary`/`pages_per_chapter`/`style_preset` 字段正确落库；空剧情摘要返回 400 `invalid_input`；每集各分镜页产出图可在章节详情查看（🟡 需 ComfyUI 真实可达）。
  - 出图风格：选定风格后，同一项目生成的**每一集、每一页** `prompt_text` 都包含完全一致的风格描述词、`negative_text` 都包含该风格的排除项；非法风格值不改动项目已存 `style_preset`；`GET /api/comic/style-presets` 返回以 `none` 打头的完整清单。
  - 人物一致性：从剧本抽取角色后，出现该角色的**每一页** `prompt_text` 都包含**逐字相同**的角色锚点、`negative_text` 都包含该角色排除项；重复抽取不覆盖已手填字段；同一角色组合在同一位置派生出的 `seed` 稳定可复现。
  - 进度与诊断：`GET /projects/<id>/progress` 返回各状态计数、百分比、章节级进度与失败原因分布（ComfyUI 离线时探测降级不影响进度数据）；`GET /projects/<id>/precheck` 返回在线 / 工作流 / 节点 / 队列体检结果与中文建议；可重试错误在 `MAX_ATTEMPTS` 次内自动退避重排，超限后落 `failed` 且 `error_message` 为中文可读文案。
  - 单页深链：`GET /pages/<id>/editor-link` 对已指定工作流的分镜返回可用 `url`；未指定工作流返回 400 `invalid_input`。
  - 主角贯穿：标记为主角的角色，其锚点出现在**该项目每一页**的 `prompt_text` 里（含剧情文本未提及该角色的页）；取消主角后，只有文本命中的页才注入；首张角色卡默认 `is_main=1`。
  - 提示词重刷：改动任一角色卡「外貌」后调用 `POST /refresh-prompts`，返回 `updated = 页数`、`changed = 页数`，且全部分镜页的 `prompt_text` 都含新外貌词；不做任何改动再刷一次，`changed = 0` 且 `base_prompt` 不变（幂等）；`requeue=failed` 时只有 `status=failed` 的页重新入队；`requeue` 传非法值返回 400。
  - 分镜重建模式：`mode=rebuild` 时返回 `removed_chapters = 旧章节数`，生成后章节数仍等于集数（不叠加重复分集），且不存在指向已删章节的孤儿分镜页 / job；`mode` 传非法值返回 400 `invalid_input`。
  - 分镜页差异化：每集剧情**句数不足**页数时，各页画面描述按 `sentences[i % len]` 循环取用（不是复制末句），且同一章内各页 `shot_note` 互不相同。
  - 出图产物加固：正向/负向节点通过 title 或内容即可被正确识别（不依赖节点顺序）；同一页再次出图后，产出目录里该页只剩 1 张最新图。
  - 剩余时间预估：有历史完成任务时 `progress` 返回 `avg_job_seconds > 0` 且 `eta_seconds > 0`；无样本时两者为 0 且前端不展示 ETA 文案。
  - 产出图回流图库：出图成功页经 `register_image` 入库后，`comic_pages.image_id` 非空且 `GET /api/gallery/<id>` 可查到该图元数据；`POST /projects/<id>/sync-gallery` 对历史项目补齐缺口（`registered>0`），对产出文件已移走的页 `missing>0` 且 `image_path` 被清空；重复调用幂等（`registered` 归零）。
  - 单页重扩写：对带 `beat_text` 的页调 `POST /pages/<id>/reexpand` 返回 `reexpanded=true`、`changed=true`、`prompt_text` 已重排；对无 `beat_text` 的页返回 `reexpanded=false`、`provider=skip` 且 `warnings` 非空；`requeue=true` 时返回非空 `job_id`。
  - 按条件重出：点「按条件重出」弹窗正常弹出并显示各范围页数（`全部页 N / 失败 M / 未出图 K`），按选定范围提交后对应页进入 `queued`；误传响应体不再导致 `TypeError: forEach is not a function`。
  - 错误码形态统一：`GET /api/error-codes` 与 `GET /api/comic/error-codes` 均直接返回 dict（约 36 条），前端 `_errorCodeMap = data || {}` 可直查；`interrupted` 类错误码返回「上次进程退出时中断，请重新出图」中文文案。
  - 运维回收：进程被杀留下的卡死任务可由 `GET /maintenance/stale` 只读体检、`POST /maintenance/reap` 回收（`requeue` 复位后重入队、`dry_run` 只统计）；应用启动时会自动 reap 一次。

## 5. 非功能性需求

- **性能**：列表接口分页上限 100；反推历史、词库学习等热点路径已做 N+1 批处理（100 条历史由 201 次查询降至 2 次）；PNG 文本块解析改为流式（5.4GB 图库实测峰值内存 24MB→8.6KB）。

- **可维护性**：业务异常统一 `AIBARError` + 全局错误处理器；跨包能力经 `core` 传递；常量集中 `resources/*.json`。
- **测试**：Python `pytest` + 前端 `node:test`；新增功能必须有对应测试，既有不回归。

## 7. 模块需求（M13 / M14 · 演员库与组图）

### M13 · 演员库（跨漫画的人物一致性基准）

> 设计动机：M12 「角色卡」是项目级资产，同一个人物在第二部漫画必须重填一遍外貌 / 服装 / 配色才能复用，长相会漂。演员库把「这个人长什么样」上升为**全局资产**——一次定妆、多部漫画复用；改演员即可批量校正所有关联角色。

- **演员表 `actors`**：与项目级 `comic_characters` 解耦。`name` / `appearance` / `outfit` / `palette` / `negative` 是定妆权威信息（不动 source_project_id 就能跨项目复用）；`seed_offset` / `base_seed` 派生确定性种子（randomize=False 重生成仍同一张脸）；`image_id` 关联图库，便于在演员库直接展示。
- **演员↔漫画角色关联 `actor_character_links`**：一个角色只能绑一个演员（`UNIQUE(character_id)` 保证），否则「以演员为基准保持一致性」会出现两个互相冲突的基准。
- **「从角色提升为演员」**：选角色卡的 `actor_id` 自动继承 `comic_characters` 的 `appearance` / `outfit` / `palette` / `negative`（不动 `name`），并把 `base_seed` 一并带过来——演员首次重生成能复现角色原脸。
- **「改演员即改全本」**：`PATCH /actors/<id>` 默认把改动同步给所有关联角色；`apply_to_characters:false` 可关闭。

### M14 · 组图（同一人物的连贯动作序列 + GIF 式连播）

> 与 M12 分镜的关键差别：**分镜跟着剧情走，每页是不同场景；组图只让同一张脸在不同动作里反复出现**，出完一组可连播成动画（像 GIF 一样播放）。不扩漫画分镜表，独立两张表 `shot_groups` + `shot_frames`。

- **「强制预设提示词」（核心机制）**：组图一次性设定 `preset_prefix`（场景/画风）/ `preset_suffix`（镜头/画质）/ `preset_negative`，帧只提供 `action_text`。**改了预设后调 `refresh-prompts` 会用当前预设覆盖全部帧**——单帧改不动提示词，这是连播时人物不漂、画风不跳的根本保障。提示词拼装顺序：`[人物锚点] → [一致性指令] → [preset_prefix] → [action_text] → [preset_suffix]`（锚点前置继承 M12 已验证的结论）。
- **连贯动作种子策略**：`seed = base_seed + order_idx * seed_step`；`seed_step=0`（默认）= 全部帧同一种子——同种子 + 不同动作文本，模型保留人物与构图只改动作，连播起来像同一人做连续动作；调大 `seed_step` 拉远动作幅度（代价是脸开始漂）。
- **串行出图**（ComfyUI 单卡排队）：`generate_group` 在后台串行跑整组；`POST /cancel` 让当前帧跑完再停（不硬杀线程，避免状态卡在 generating）；`POST /frames/<id>/regenerate` 单独重出一帧（整组跑时让位）。
- **连播**：点击组图封面打开播放器，已出图的帧全部预加载到 `Image` 对象，播放时只切 `src`（不闪白）；速度档围绕本组 `frame_interval` 动态生成；快捷键空格（播放/暂停）、←/→（逐帧）。
- **逐帧管理**：弹窗默认**逐帧卡片视图**（缩略图 + 状态徽标 + 上移/下移/重生成/删除 + 错误信息），多行文本框降级为「批量编辑」折叠入口。
- **可靠性守护**：进程被杀时跑着的帧会卡在 `generating`——`_claim_frame` 用 `status<>'generating'` 守门防抢同一张卡，但代价是「救不回来」。`comic/recovery.py::reap_stale_frames` 在启动期（15 分钟阈值）+ 手动路由 `POST /api/comic/maintenance/frames-reap` 双重兜底，复位为 `failed`（带中文原因），不自动入队避免偷偷重跑用户已认可的图。
